# MixStudio analysis and application audit

Date: 16 October 2026. Baseline: `9f464ca` (0.19). Targeted fixes: 0.20.

The beat/BPM precision changes pass controlled ground-truth tests, and several editing and source-safety defects are fixed. The wider audit found significant remaining renderer, transition and input-validation problems. Address those before extending the feature set. Passing the current suite does not mean the open findings below are fixed.

## Analysis changes and measured precision

The coarse onset-energy comb could report the wrong fractional tempo even when the dynamic beat markers were accurate. In the 127.98 BPM test, the old estimate was 128.191007 BPM: approximately 594 ms of accumulated fixed-grid error over six minutes. The new estimate is 127.980008 BPM, approximately 0.024 ms over the same interval. The 128.025 BPM test gives 128.025002 BPM and approximately 0.007 ms of drift. These figures describe estimated steady-tempo drift, not rendered audio latency.

The steady estimate now fits actual sample-level attack observations, not interpolated or smoothed grid positions. It requires at least 32 observations, a 32-beat span, 60% coverage within that span, a 90th-percentile residual below 10 ms and agreement within 2% of the coarse tempo. Variable or sparse evidence retains the coarse estimate. A single kick followed by digital silence no longer manufactures a dynamic grid or changes BPM through inferred silent beats.

Integer BPM snapping is removed. Missing interior attacks are interpolated between supported attacks before smoothing; a long missing-kick test initially had a 20.7 ms beat-position p95, reduced to 0.27 ms after this correction. Musical tempo changes retain their dynamic timing rather than qualifying for a steady fit.

Stereo rhythm analysis compares onset evidence in mid and side projections, preferring mid when evidence is close. This handles opposite-polarity stereo without allowing a louder sustained side-channel pad to cancel centred kicks. Key analysis retains its existing input. Short-audio autocorrelation now rejects lags outside the available envelope instead of subtracting past zero.

Tests use the generated event timestamps as independent ground truth. Timing metrics omit boundary beats; the long steady tests also verify consecutive matched beat indices, preventing extra or skipped interior beats from hiding behind nearest-beat error. Separate tests exercise stereo polarity, centred kicks with a sustained wide pad, sparse evidence, short audio and an end-to-end tempo ramp. This is a small controlled corpus, not evidence that arbitrary real tracks have submillisecond grids or correct musical downbeats.

Two local 44.1 kHz recordings were also decoded and analysed without changing their saved project. Their estimates were 125.003695 and 123.999350 BPM against previously saved 125 and 124 BPM. Their true beats and downbeats have not been annotated, so these are plausibility checks, not accuracy scores. The previously referenced `test.json` was unavailable; the remaining dynamic-grid project supplied these recordings.

## Fixed application findings

| Finding | Original effect | Correction and verification |
|---|---|---|
| Library never refreshed old detector results | Cache upgrades left existing library BPM/key values stale indefinitely | Persist analysis version per entry; invalidate derived fields while preserving tags. Migration regression passes. |
| Stale library analysis jobs | A cancelled job could overwrite results after a rescan | Accept analysis results and completion only for the current, uncancelled token. Tests cover cancelled results, mismatched tokens and stale completion. |
| Byte-backed drop filename collision | A second `song.wav` overwrote an earlier source; path components could escape the temporary directory | Keep sources under unique persistent directories with a safe basename, exclusive creation, restricted file mode and synced writes. Same-name and traversal regressions pass. Existing legacy temporary sources are not migrated. |
| Duplicate automation points | Three points at one timestamp produced inverted drag bounds and a panic | Replace equal-time points; existing invalid drag bounds preserve time while allowing value edits. Regression and UI-path review pass. |
| Auto-tempo reorder used old ratios | A 70/140/140 BPM reorder changed 64-beat overlaps to 204 beats on the following frame | Resolve ratios against the requested order before layout. Next-frame stability regression passes. Manual/ramp relayout remains an open limitation below. |
| Split erased an explicit timing ratio | An 80 BPM clip at ×1.5 moved/truncated its right fragment after the next ratio resolution | Preserve the explicit ratio while clearing other transition settings. Ordinary and arranged split regressions pass. |
| Arbitrary Unicode keys panicked | Imported `F♯` could crash key filtering/sorting through a byte-boundary split | Share a UTF-8-safe Camelot parser; unsupported notation stays unknown. Sorting/filtering regression passes. |

## Open findings by priority

P1 means a major correctness problem requiring the next maintenance pass. P2 means a material correctness or reliability defect. “Reproduced” means an isolated test exercised the actual modules or exact affected functions; “inspection” means a verified code path without a complete runtime reproduction.

### Renderer and transport

| Priority | Finding and evidence | Required change |
|---|---|---|
| P1 | **Key lock silently stops at snapshot track index 64.** Reproduced in `engine.rs`: a 440 Hz source at 120→126 BPM renders at 461.48 Hz at index 64, versus 440.48 Hz at index 63. Finished earlier clips still consume indices. | Prepare enough stretch state outside the realtime callback or assign state by active voice. Test long sequential playlists and overlaps. |
| P2 | **Timeline FX after the first 16 are ignored.** Reproduced: the 17th FilterSweep is identical to no FX. UI additions are unbounded; Scratch also consumes an index. | Prepare state for supported block counts or explicitly enforce and explain a limit. |
| P2 | **Deleted FX contaminate newly added FX.** State is tied to vector position. Reproduced: removing an Echo and its audio, then adding a new Echo on silence emits an old-audio peak of 0.0765. | Give blocks stable identity and reconcile/reset state after removal, replacement, kind or target changes. Preserve state for unchanged edits. |
| P2 | **Export truncates effect tails.** App export ends at track length +16 beats although tails can reach 64. Reproduced omitted Echo output peaks at 0.061965 after the export boundary. | Include the latest effect end and its extra half-beat fade in export length. |
| P2 | **Loops lose overshoot and render beyond their end.** At 8 kHz/120 BPM, a `[0,0.1)` beat loop reports beat 0 after 4,096 frames instead of 0.024. Longer loops also accumulate a partial-block error. | Split rendering at boundaries and retain sample/fractional timing across wraps. |
| P2 | **Seek retains deck filter history.** Reproduced with active low-pass filtering: playback after Seek(0) differs from a fresh renderer by a 0.047939 peak. Click state is retained too. | Reset transport-dependent biquads, delay positions and metronome state. |
| P2 | **Tempo-ramp timing depends on callback partition.** Reproduced 120→240 BPM over 16 beats at 8 kHz: at the calculated duration, 256-frame blocks reach 15.955630 beats and 31-frame blocks reach 15.994421. | Share accurate time/beat integration between renderer and duration calculation. Test terminal beat and callback independence, not just allocated sample length. |

The existing host-default audio buffer fix remains intact. This patch does not alter realtime DSP or claim to resolve the renderer findings.

### Editing, input and storage

| Priority | Finding and evidence | Required change |
|---|---|---|
| P2 | **Splitting inside an overlap changes the transition.** Reproduced: splitting incoming at beat 200 truncates the existing transition from `160..240` to `160..200`, silencing the outgoing track early. Explicit ratio preservation does not fix this. | Preserve transition identity/timing across contiguous split fragments. Compare audio before/after an otherwise neutral split. |
| P2 | **Phrase placement ignores ratios and some arranged occurrences.** Inspection: source phrase beat 112 at ×2 belongs at mix beat 224, but several placement paths add 112 directly. | Convert source phrases through the grid and arranged occurrences consistently in drawing and layout. |
| P2 | **Manual/Fixed ramp relayout samples tempo at old positions.** Inspection: requested order is now used, but fixed-curve ratio references precede placement. | Resolve layout/ratios consistently at final positions and test stability on subsequent frames. |
| P2 | **Truncated audio is accepted as successful decode.** Reproduced with the existing decoder: a WAV declaring one second but truncated to 0.25 seconds returns success. Packet/decoder errors are broadly swallowed. | Distinguish clean EOF from corruption, check reliable frame counts with format-specific delay/padding tolerance, and surface incomplete decoding. |
| P2 | **Project/recovery input lacks structural validation.** Inspection: a deserializable track with `lane:4` reaches four-element renderer indexing. Numeric mode fields, tempos, maps and ranges also need semantic checks. | Validate before project activation/recovery and retain the current document on rejection. Add malformed-file regressions. |
| P2 | **MP3 export uses a deterministic adjacent temporary filename.** Inspection: `.mixstudio-tmp.wav` is overwritten/deleted and can collide with user files or another export. | Use an exclusively created unique temporary file and isolated cleanup. |
| P2 | **Partial folder scans discard metadata for unreadable subtrees.** Inspection: traversal errors still mark the root available, so absent results are removed. | Preserve entries below failed subtrees and distinguish partial from complete scans. |

### Further reliability and analysis work

- **Analysis confidence:** relative attack thresholds can count a tiny noise floor as evidence; a single kick plus very quiet noise still produces a populated dynamic map, although the new steady BPM fit is rejected. Add attack-contrast/SNR and periodic-support measures. Surface uncertainty rather than treating every generated marker as supported.
- **Stereo waveform display:** waveform peaks still use the mid projection; opposite-polarity sources can have a weak/flat waveform even when their new rhythm analysis succeeds. Use phase-safe channel energy for waveform display in a separate visual regression.
- **Musical ambiguity:** the detector retains a dance-tempo octave bias; half/double time and bar/downbeat phase need a separately labelled reference corpus. Swing, syncopation, percussion-only recordings, sustained bass and soft attacks need broader real-music validation. Flex stays an explicit experimental choice.
- **Long exports:** rendering and encoding hold whole-mix buffers. One hour at 44.1 kHz needs roughly 2.2 GB for stereo floats plus a 24-bit WAV buffer, excluding decoded sources. Stream rendering/encoding; exercise RIFF size limits and low-memory failures.
- **Cached model integrity:** `stems::ensure_model` accepts an existing model by size before checking its advertised SHA-256. Verify cached bytes before session use; test corruption without downloading a model.
- **Engine DJ database snapshots:** database and WAL are copied separately with WAL-copy errors ignored. Inconsistent imports during concurrent writes are suspected; reproduce under WAL writes before choosing a snapshot strategy.

## Verification and scope

The audit reviewed analysis, beat maps/checking, grid correction, project models/sections, editor/comparison state, playback/render/export/FX/scratch/stems, persistence/recovery, library scanning and imports. Independent read-only reviewers reproduced audio and editing failures and reviewed the targeted fixes. Two issues in the first precision draft were caught during review, reproduced, corrected and regression-tested before release: broadband stereo selection and fitting inferred silent beats.

`cargo clippy --all-targets` completes with 102 binary warnings and 107 test-target warnings (102 shared), mainly compact formatting, range loops, complexity and test construction; these remain cleanup work. Its blocking approximate-constant lint in a selftest expectation was replaced with the exact standard constant. This is not a warning-free lint result.

The ordinary Rust suite passes **62 tests**, with **5 explicitly ignored local/device diagnostics**. The synthetic `--selftest` passes, including decoded demo BPM/key/downbeat, rendered overlaps, stretch pitch, stems, drift, soft intro, automation, grids, scratch, export formats and round trips. The local source-analysis diagnostic also passes. The updated native Beatgrid view was rendered and visually checked using isolated generated demo data.

These checks do not constitute a dependency vulnerability scan, a cross-platform certification, an annotated commercial-music benchmark or a fresh physical-device listening test. Open reproduced findings remain open regardless of the suite result. The next work should cover renderer state/capacity and transport timing, followed by neutral split/phrase semantics and input/export hardening, before more features.
