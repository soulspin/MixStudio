# MixStudio 0.30 application audit — 2026-10-27

Scope: the whole application at `main` (0.30.0-beta), split into five areas — audio engine and export; analysis and beat tools; mix model and editing; application shell, state and persistence; library, import and stems. Each area was audited independently. Every finding below labelled **Reproduced** has a failing (or measuring) test that was re-run during verification; **Inspection** means a verified code path without a runtime reproduction. Known items from [AUDIT-2026-10-16](AUDIT-2026-10-16.md) and the [maintenance record](MAINTENANCE-2026-10-16.md) are not repeated unless they regressed (none did).

Severity: **High** loses work, crashes or blocks the user. **Medium** gives wrong audio, wrong data or a confusing hang in realistic use. **Low** is an edge case, a cosmetic defect or a cost.

**Status:** group 1 (findings 1, 2, 3, 4, 9, 16, 18) is fixed with regression tests; the remaining findings are open.

## 1. Audio engine and export

**5 — Key lock loses treble when the device rate differs from the source** · `engine.rs:240-249` (`Polyphonic::fill`)
Source audio is converted to the device rate by linear interpolation before the stretcher, which low-passes and aliases. 44.1 kHz sources on a 48 kHz device (the usual PipeWire default) with key lock on lose −0.37 / −1.46 / −2.76 dB at 5 / 10 / 14 kHz; export at 44.1 kHz, 48→48 playback and varispeed are unaffected, so playback and export no longer sound alike. *Reproduced* (`audit_keylock_resample_hf_loss`). Fix: Hermite or short windowed-sinc conversion, or stretch at the source rate and resample the output.

**10 — Loop wraps are hard cuts** · `engine.rs:533-539`, `render_clocked`
A 1-beat loop over a sine jumps 0.794 at the wrap against a normal maximum step of 0.0072. Seek, pause and loop on/off (`audio.rs` `Transport::change` → `reset_transport`) switch blocks abruptly and zero EQ/echo/FX state, cutting tails. *Reproduced* (`audit_loop_wrap_jump`). Fix: a few ms crossfade at the wrap and a fade-out/in ramp on epoch change or pause.

**11 — Deck filter re-entry click** · `engine.rs:505-506`
LP/HP filters only run while |filter| > 0.001 and keep stale state. Automation −0.3 → 0 → negative again jumps 0.098 at re-entry (5× the normal slope). *Reproduced* (`audit_filter_reentry_stale_state`). Fix: clear state on re-engage, or always run and crossfade.

**22 — Device errors are silent and permanent** · `audio.rs:199`
A stream error stops the worker; the UI still believes a stream exists, so the "No audio" notice never shows and Play does nothing until restart (USB/Bluetooth unplug, PipeWire restart). *Inspection.* Fix: publish the error, show it, and rebuild the stream via `audio::start()`.

**23 — Mono output plays only left** · `audio.rs:69`, `engine.rs:367`
A right-only source on a 1-channel device peaks at 0. *Reproduced* (`audio_mono_device_drops_right`). Fix: output (L+R)/2 when `ch == 1`.

Low:
- **26** Metronome clicks off-beat after every seek, resume or loop wrap (peak 0.495 when seeking to beat 0.5) · `engine.rs:525`. *Reproduced.* Fix: start clicks only on a crossed beat boundary.
- **27** No smoothing on deck volume, mute/solo, master or song gain: a mute toggle jumps 0.244; fader drags zipper; Monitor A/B switching clicks · `engine.rs:485,514,522`. *Reproduced.* Fix: 5–10 ms per-sample ramps.
- **28** `interp32` allocates a `Vec` per call inside `track_mods`, several times per sample: transitions with curves render 1.35× slower · `model.rs:539-541`. *Reproduced.* Worker thread, not the device callback.
- **29** Stem-volume automation edits do not flush the key-lock stretcher's buffered input (~150 ms of old gains) · `engine.rs:315-317`. *Inspection.*

Improvements: allocate the stretcher only for key-lock voices (512 KiB+ each today); allocate FX buffers per effect kind (a 4 s delay for every block today); update deck EQ coefficients every 16–32 samples; offer 48 kHz export and dither 16-bit WAV; fail clearly instead of wrapping the u32 WAV size beyond ~4.5 h at 24-bit; show the underrun counter; accept I32/U16 device formats.

## 2. Analysis and beat tools

**4 — NaN/inf samples panic analysis** · `analysis.rs:915` (also 717, 930, 1015, 1034)
`decode()` passes non-finite samples through; `partial_cmp().unwrap()` then panics. Via `load_files` the worker dies, the rest of the batch never loads and the "Analysing…" spinner (and continuous repaint) never stops. *Reproduced* (`audit_nan_sample`, `audit_inf_sample`; a float WAV with one NaN decodes with count 1). Fix: sanitise in `decode()` and use `total_cmp`.

**19 — MP3 encoder delay not removed** · `analysis.rs:289`
`FormatOptions::default()` has gapless off. A LAME MP3 with a kick at 0.500 s decodes it at 0.525 s; with gapless on, exactly 0.500 s. Imported Rekordbox/Traktor/Serato grids and cues therefore sit ~25 ms off on MP3s, and the same song as WAV and MP3 gets grids 25 ms apart. M4A (0.523 s) needs the iTunSMPB/edit-list delay read separately. *Reproduced* (`audit_lossy_decode`, `audit_gapless`). Fix: enable gapless, bump `ANALYSIS_VERSION`, and migrate saved MP3 clip offsets once.

**20 — Flex segmentation is cubic** · `analysis.rs:985-992`
`sse(i,j)` is recomputed inside an O(k²) loop. Measured: 0.10 s for 10 min, 2.0 s for 30 min, 15.6 s for 60 min (another run: 41.9 s), and it runs on every analysis. Two-hour mixes exceed the 180 s library timeout. *Reproduced* (`audit_long_file_speed`). Fix: prefix sums make `sse` O(1); compute Flex only when selected.

**25 — Streamed WAVs rejected** · `analysis.rs:307,338`
A data size of 0xFFFFFFFF (ffmpeg to a pipe, some recorders) is taken as exact: "incomplete audio: expected 1073741823 frames". *Reproduced.* Fix: treat oversized/placeholder sizes as unknown.

Low:
- **30** One bad AAC packet rejects the whole m4a, while the same damage in MP3/Ogg is silently accepted · `analysis.rs:319`. *Reproduced.* Fix: skip and count decode errors; fail above a threshold.

Clean: short/odd sample rates (8–192 kHz), 24-bit/u8/s32 WAV, truncation of FLAC/WAV/m4a, beatmatch measurement units and signs across different tempos, two-anchor corrections, the 0.30 `steady_clock`/`kick_phase` checks with realistic hi-hats, cache versioning, Camelot/harmony mapping, determinism.

Improvements: make `automix::optimize` incremental or move it off the UI thread (1.8 s for 400 tracks); compute phrase bars from the beat map rather than a linear grid; write analysis cache files atomically.

## 3. Mix model and editing

**1 — A Single-beat edit can make the project unsaveable** · `beatmap.rs:153-154` vs `validation.rs:12`
`move_single` clamps beats 5 ms from their neighbours; validation requires 6 ms. Pressing +10 ms repeatedly in Single mode (or dragging a beat into its neighbour) leaves 5.000 ms spacing, after which save, recovery checkpoints and close/open protection all fail ("App kept open: could not protect unsaved changes"). *Reproduced* (`probe_single_beat_clamp_makes_project_unsaveable`). Fix: one shared minimum-spacing constant.

**2 — Fade drag panics** · `app.rs:1611`
`fade_in.clamp(0.0, len - fade_out)` panics when the other fade exceeds the clip, which `Mix::split` (`model.rs:439`) and `delete_section` (`sections.rs:105`) produce and validation accepts. Split a 64-beat clip with a 48-beat fade-in at beat 16, drag the left fragment's fade-out: panic "min > max, max = −32". *Reproduced* (`probe_fade_drag_after_split`). Fix: clamp to `(len − other).max(0)`, clamp fades in split/delete/set_edge, validate the sum.

**9 — Delete or Undo during an edge drag overwrites a track** · `app.rs:1605-1607`
`TlDrag::Edge` writes `tracks[ti] = original` every frame and nothing clears drag state on remove/undo/redo. Pressing Delete while holding a trim handle replaces the next track with the deleted one; Ctrl+Z during a drag is immediately re-applied without an undo entry. `auto_track` also survives removals and reopens on another track. *Reproduced* (`audit_delete_during_edge_drag_resurrects_track`). Fix: clear all drag state in `remove_sel`, `do_undo`, `do_redo` and `fix_sel`, or ignore these keys during a drag.

**12 — Splitting inside a fade changes the sound** · `model.rs:452,459`
The right fragment gets `fade_in = 0` while the left keeps a fade longer than itself: gain just after the split jumps 0.058 → 0.170. *Reproduced* (`probe_split_inside_fade_render`). Fix: divide the fade between fragments with an offset.

**13 — Relayout treats split fragments as songs** · `app.rs:357,853,854,1786`
Playlist ⏶/⏷, Set all overlaps, Overlap outros with intros and Auto-order use `main_order()` (one entry per fragment). After a split, "Set all overlaps" leaves a 16-beat gap inside the song and puts its halves on different decks. *Reproduced* (`probe_relayout_after_split_overlaps_fragments`). Fix: use `main_groups()` and move each group as a unit.

**14 — Grid edits on one fragment break the song** · `app.rs:1838,1928`
`,` / `.`, Beatgrid ±ms, Set downbeat, Reset and grid mode edit one fragment only. A 1 ms nudge separates the fragments by 0.002 beats, the logical transition shrinks from 160–240 to 160–200, and a later track removal puts the halves on different decks. *Reproduced* (`probe_nudge_fragment_breaks_logical_group`). Fix: apply source-grid edits to every sibling, or block them for fragments.

Low:
- **31** A failed split, or any no-op drag, wipes the redo history (`snapshot()` then `undo.pop()`) · `app.rs:249,416`. *Reproduced.*
- **32** `add_track` places a track before its beat ratio is resolved: a 70 BPM track after a 140 BPM one overlaps 65.3 beats, then 74.7 after the next frame · `model.rs:408`. *Reproduced.*

Clean: the oldest project format still loads and validates; serde undo round-trips are exact; `samples.rs`, `recovery.rs`, section ripple, stem-volume and sample UI bounds; lanes ≥ 4 and invalid modes are rejected at load.

Improvements: one "edit the logical song" helper in `Mix` for all fragment-aware edits (fixes 13 and 14 and their variants); the playlist relayout hardcodes 16 bars instead of the chosen overlap; tighten validation to the ranges the UI produces (zero-length clips, ±16 volume); the Key field creates an undo step per keystroke; edits silently reverted while locked should say so.

## 4. Application shell, state and persistence

**6 — Edits during a Library preview use the hidden preview position** · `app.rs:410,612,1931`; `library_listen.rs:52`
While a preview plays, the engine playhead is in the previewed file's beat space; the timeline shows `restore_beat`, but Ctrl+E, paste, `,`/`.` and playhead snapping read `beat()`. With the mix playhead at beat 10, Ctrl+E splits at beat 21.33. *Reproduced* (`audit_split_during_library_preview_uses_preview_position`). Fix: one `edit_beat()` returning the timeline position, or stop the preview before edits. *Introduced in 0.30.*

**7 — Timeline clicks during a preview are lost** · `app.rs:1013,1457`, transport buttons `864-872`
Clicking the ruler moves the preview to an unrelated source position; stopping the preview restores the old mix playhead. *Reproduced* (`audit_timeline_click_during_preview_is_lost`). Fix: update `restore_beat` (or stop the preview) on timeline seeks. *Introduced in 0.30.*

**8 — Context-free Delete** · `app.rs:725,1351,1458`
Selecting an FX block or a transition does not clear the clip selection, and Delete always removes the selected clip — from Effects, Library or anywhere else. `,` `.` `Z` likewise act on the timeline from the Library. *Inspection.* Fix: route Delete by context and clear `sel` when something else is selected.

**24 — Undo merges a late-loaded track with a later edit** · `app.rs:293-299,682`
`load_files` snapshots at request time; the track arrives later without its own step. Drop a file, change a gain while it analyses, Ctrl+Z: both disappear. All-failed loads leave an empty undo step, and drops skip the arrangement-lock check. *Reproduced.* Fix: snapshot on arrival, as Library batches already do.

Low:
- **33** Adding Scratch with the default "Master" target silently lands on Sample 2 · `fx.rs:44`, `app.rs:486`. *Reproduced.*
- **34** The app redraws at 10 Hz when idle and rebuilds/sends a playback snapshot every frame · `app.rs:713,733`. *Inspection.*
- **35** Top-bar mode and bottom tab get out of sync; "Studio" alone does nothing · `app.rs:795,829`. *Inspection.*

Clean: stale-result guards on every background message; state reset on project activation; close and switch protection; recovery restore/discard; relink; transition workbench, Compare, levels and harmony panels.

Improvements: shortcut help is missing Ctrl+E, Ctrl+C/V/D, Escape, Z, `,`/`.`, Enter/Ctrl+A and the section meaning of Delete; "🎧 Headphone cue (v2)" does nothing, ✂ means remove (not split) and ⏺ exports; repeated Ctrl+S/Export opens several dialogs; `mixstudio project.json` and `--help` are ignored; name, metronome and stem-style changes are not undoable.

## 5. Library, import and stems

**3 — Deep XML nesting crashes the app at every start** · `import.rs:78-116,142,171,188`
The XML tree has unlimited depth; dropping it and walking Rekordbox/Traktor/iTunes nodes recurse. A corrupt ~2.4 MB `rekordbox.xml` with 100k unclosed tags aborts the process (stack overflow, not catchable), and because imports reload at start, the app crash-loops until `library.json` is edited. *Reproduced* (`a3_deep_nesting_parser_only`: SIGABRT). Fix: cap nesting depth in the parser and the walkers.

**15 — Removing an import leaves a stale path map** · `library.rs:354,357`; `app.rs:272-276`
Until the reimport finishes (up to 120 s), a track added to the mix receives another library's cues and imported beat grid. *Reproduced* (`a3_remove_import_leaves_stale_ext_map`: `a.mp3` resolves to `b.mp3`, 90 BPM, "B cue"). Fix: rebuild `ext_map` in `remove_import`.

**16 — One non-finite number wipes the index** · `library.rs:158-167`
serde_json writes NaN/inf as `null`, which fails to load as `f64`, and `read_json` falls back to an empty index; the config file has the same silent default and the next save overwrites the user's folders. *Reproduced* (2 entries saved, 0 loaded). Fix: sanitise before saving; back up and log an unreadable file instead of defaulting.

**17 — Transient timeouts become permanent errors** · `library.rs:234,265,282,381`
A 15 s tag timeout (a spinning-up USB drive) or a 180 s analysis timeout is stored on the entry; unchanged files are reused and never re-analysed. *Reproduced* (`a3_transient_timeout_is_permanent`). Fix: do not persist timeouts, or retry them on rescan.

**18 — Decoder panics** · `library.rs:178,283`; `library_drop.rs:24`; `library_listen.rs:31`
Symphonia panics on a WAV with sample rate 0. The analysis queue records it as "analysis timed out" (then permanent, see 17); drop and preview threads have no `catch_unwind`, so loading never finishes and the preview stays on "Loading…". *Reproduced* (`a3_read_tags_zero_rate_wav`); the UI hang is by inspection. Fix: report panics distinctly and wrap these loads.

**21 — Engine DJ 2.x relative paths** · `import.rs:295`
`base = db.parent()` (`Database2`), but Engine 2.x paths are documented by libdjinterop and Mixxx as relative to `Engine Library`, so every track would show as missing. Behaviour reproduced (`a3_engine_relative_path_base`); the format claim is not verified against a real database, and the self-test fixture encodes the current assumption. Fix: probe both bases.

Low:
- **36** iTunes playlists with repeated persistent IDs expand exponentially (4 duplicates did not finish in 10 s; the thread keeps burning CPU after the import times out) · `import.rs:211-216`. *Reproduced.*
- **37** Timed-out analyses keep running while the worker starts the next file, so the worker limit is not enforced (multi-GB decodes in parallel on long mixes) · `library.rs:282`. *Inspection.*
- **38** Symlinked subfolders are skipped silently · `library.rs:191-192`. *Reproduced.*
- **39** The Details "Folder" column strips the root with a string prefix: a file under `/Music/House2` with a root `/Music/House` shows "2" · `library_ui.rs:221`. *Inspection. Introduced in 0.30.*
- **40** Stems and the analysis cache hard-code `$HOME/.cache` and `$HOME/.local/share`, ignoring `MIXSTUDIO_CACHE_DIR`/XDG/Windows paths · `stems.rs:33-34`, `analysis.rs:664`. *Inspection.*
- **41** Smaller parsing issues: `%+1` accepted as a hex escape; `file://server/share` becomes relative; the Engine temp dir leaks when a copy fails; the stem model download has no read timeout.

Clean: Camelot conversion (all 24 Engine keys), Traktor key, Rekordbox/Traktor cue units, Traktor grid markers, path remapping, entity unescape, Serato TLV/crates, scan/analysis cancellation, folder removal during a scan, BPM ±% with half/double tempo, key filter, Enter/Ctrl+A gating.

Improvements: use imported BPM/key as a fallback in the table and filters; a fixed worker pool for scanning (today one thread per file in batches of 4); lazy or parallel existence checks for large imports on a NAS; accumulate only the three used stems (≈85 MB/min today); stem cache eviction and orphan cleanup; keep `/Volumes/<name>` for Traktor paths on macOS.

## Suggested order

1. **Data safety and crashes (1, 2, 3, 4, 9, 16, 18):** each is small and self-contained, and each can lose work or stop the app.
2. **Preview regressions from 0.30 (6, 7, 39):** contained in this week's code.
3. **Sound quality (5, 10, 11, 27, 26):** a shared "ramp on change" helper covers most clicks; the resampler fix restores treble on 48 kHz systems.
4. **Split-fragment consistency (12, 13, 14):** best solved together with one logical-song editing helper.
5. **Import/library robustness (15, 17, 19, 21, 25, 36–38, 40)** and the remaining Low items.

## Verification method

Each area was reviewed in its own copy of the repository, with throwaway tests added to reproduce suspected defects using synthetic audio and temporary fixture files. No personal music, configuration or network downloads were used. The tests named above were re-run during verification and failed (or measured) as described. They are not part of the code base; they remain available in the audit worktrees until those are removed.
