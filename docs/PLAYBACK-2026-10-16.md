# Playback repair in 0.21.2

The final overlap of a saved five-track mix exposed two problems: custom WSOLA matching could cancel wide stereo content, and its time-domain matching still produced metallic vocals during a roughly 137→125 BPM tempo change. The user heard a partial improvement from stereo matching, then preferred a separate Signalsmith Stretch comparison. No user recordings or project files are included in this repository.

## Changes

- Use pinned `signalsmith-stretch` 0.1.3 for polyphonic key lock. Source-grid timing determines rounded absolute input endpoints; source audio is resampled to the engine rate. Seek history plus explicit input/output latency compensation keeps output on the mix grid. Normal playback and export share this renderer.
- Preserve the existing cached-grain treatment for loops shorter than a synthesis hop, with per-channel WSOLA energy/similarity so opposite-polarity stereo cannot disappear from matching.
- Continue compatible logical fragments through the same stretcher/FIFO. Prepare render order by visible start time, so fragment storage order does not change handoff. Require shared source map, audio/stem identity, source continuity, mutes and matching stem routes. Independently edited fragments start fresh.
- Reset buffered input and FIFO together when actual tempo or source treatment changes. Unchanged snapshots keep history. Stem input processing uses its source sample's arranged occurrence; track gains and fades use audible output beats.
- Move DSP to an audio worker with eight pooled blocks of 512 stereo frames. Hardware callbacks copy finished samples without allocating, waiting or running FFT/WSOLA work. Seek, pause and changed loop ranges invalidate both queued and partly consumed old blocks. The playhead and meters follow consumed samples; paused meters clear.
- Retain the host-default device buffer. The internal render queue holds up to about 93 ms at 44.1 kHz, in addition to device latency. Seek/pause/loop changes discard old queued audio; other control changes travel through that queue. Count active callback starvation for diagnostics.

## Verification

- A wide-stereo regression previously fell to RMS 0.016–0.032 instead of approximately 0.300 at 440 Hz. Channel-wise matching retains the level. Bass, polarity and multiharmonic cases now pass through the polyphonic backend.
- A synthetic six-tone chord at the saved pair's tempo ratio retained only 72.06% of spectral energy within ±3 Hz of its original harmonics under WSOLA. The new backend retains effectively 100% in this controlled test. This is a regression metric, not a general listening-quality score.
- Existing strict grid tests pass: selective intro/outro key lock remains within 1.97 ms of the mix grid in the measured case, with boundary steps 0.0008/0.0004. The middle remains dynamic. No timing or boundary thresholds were relaxed.
- A repeated-split/reordered-fragment render is unchanged within 1e-6. A tempo edit matches a freshly primed reference instead of replaying input/FIFO from the previous tempo.
- Nine buffer tests cover starvation, partial/queued epoch invalidation, pause, consumed clocks/meters, loop wrap, unchanged snapshots, private worker lookahead, recycling and lifecycle/error handling.
- A read-only render of the actual final overlap produces 71.459 seconds at both 44.1 and 48 kHz. Static and repeatedly updated production snapshots have sample difference zero. Measured render time is 3.8–4.0 seconds CPU; peak 512-frame DSP work is about 2.8 ms, now performed on the worker.
- A real device test on the saved final overlap measured 4.011 seconds of consumed timeline over 4.032 seconds wall time (ratio 0.995), with zero callback underruns after 20 ms warmup while production snapshots updated repeatedly.

Final verification: **118 ordinary tests passed**, with five opt-in diagnostics ignored by default. The release CLI selftest passed **122 executed checks**; model separation was skipped because its model was not downloaded. Release build and Clippy completed; existing lint warnings remain. Independent read-only review found no release blockers. The native app was also opened with isolated generated demo data to check startup and layout.

## Build and limits

The new binding requires a C++14 compiler and libclang at build time. The Rust wrapper, Signalsmith Stretch and Signalsmith Linear are MIT licensed; their notices are retained in [TIME-STRETCH-LICENSES.md](TIME-STRETCH-LICENSES.md).

The queue absorbs ordinary rendering bursts, but sustained overload can still exhaust it; the callback then emits silence and increments the underrun count. Extreme tempo ratios, dense projects, other devices/backends and other operating systems need separate validation. Abrupt live tempo/source edits re-prime processing; this release does not claim seamless automation of arbitrary source replacements. Broader beat/downbeat analysis research from the original audit remains open.
